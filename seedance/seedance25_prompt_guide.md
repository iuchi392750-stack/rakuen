# Seedance 2.5 プロンプト大図解(要約)

出典:ByteDance / Dreamina「Dreamina Seedance 2.5 Prompt Guide」(Feishu Docs, 2025-07-31更新)

> **全技法が還る唯一の原則:モデルに推測させない。**

**動画プロンプトを書く前に必ずこのファイルを読むこと。**

---

## 数値の上限

| 項目 | 上限 |
|---|---|
| 参照素材の合計 | 50(画像・動画・音声の合計) |
| 画像 | 最大30枚 / 1枚あたり4K以下 |
| 動画 | 最大10本 / 合計30秒以内 |
| 音声 | 最大10本 / 合計30秒以内 |
| 生成尺 | 最大30秒(ステージ分割で組む) |
| 被写体 | 1〜8主体(超えると不安定) |
| 絵コンテ | 15コマまで(線画・文字ラベルは最小限) |
| 編集の誤差 | 最大0.3秒(尺はほぼ元動画のまま固定) |

## FIG 01 — プロンプトは5ブロック

必須は先頭だけ。**設定値(比率・尺・解像度)はプロンプトに書かない。**

1. **【必須】主体 + 動作** — 誰が何をするか。これが土台
2. 場所と環境 — 時間・天候・空間関係
3. ビジュアル — 光・色・質感・空気感
4. カメラ・カット — サイズ・アングル・移動
5. 音声 — 台詞・声質・環境音・音楽

## FIG 02 — 素材は「使うもの」と「使わないもの」を書く

アップロードしただけでは、その画像の何を採用するかモデルには分からない。背景・人物・構図が勝手に混ざる。

- **✕** 「@Image 1〜4 が4人を定義する」→ 顔と服が入れ替わる
- **○** 1体ずつ名前を付けて紐づける:`@Image 1 = <修復士> 外見・髪型・服装のみ` / `→ 画像内の人物は使わない`
- **画像内の文字ラベルに頼らない。**対応関係はプロンプト本文に書く
- 多方向のビューは1枚のコラージュに詰めず、ビューごとに別画像へ分ける
- **個数まで固定する**:「4枚は同じ1台のデスクライトを定義する。出力には常に1台だけ映す」

## FIG 03 — 音は4種類の括弧で区別

| 記号 | 用途 | 例 |
|---|---|---|
| `( )` | 音楽 | (柔らかくリズミカルなピアノが背景に流れる) |
| `< >` | 効果音 | \<遠くでベルが鳴る\> |
| `{ }` | 台詞 | {おかえりなさい。} |
| `【 】` | 字幕 | 【第一章:出発】 |

**台詞の前に言語を宣言する。** 公式:`言語 + 地域・訛り + 話し方 + 話者 + {台詞}`
宣言がないと意図しない言語や訛りで発話される。

## FIG 04 — 素材は種類ごとの箱に仕分ける

`[CHARACTERS]` / `[PROPS]` / `[SCENES]` / `[MOTION & AUDIO]` に分類。

- **✕** 全素材を同時に画面へ出させる → 人物も小道具も溢れて破綻
- **○** 場面ごとに使う素材を選ぶ(使用素材・出来事・終了状態を書く)
- 同じ人物が複数場面に出るなら**主体プロフィール**を1ブロック作り、外見・固定小道具・登場場所・禁止事項をまとめる

## FIG 05 — 長尺は「1ステージ = 1変化」

**終わりに見えているものを書く。** 終了状態は次のステージへそのまま引き継がれる。
「感じ」ではなく、**フレームを止めて確認できる事実**で書く。

各ステージ:`初期状態` → `主要イベント(1つだけ)` → `終了状態`
最後に「一貫性の維持」として人数・服装・小道具の所有・空間の向き・音の関係をまとめる。

## FIG 06 — 秒数は編集点ではなく「時間の予算」

通常の語りはステージ分割で足りる。秒指定は受け渡し・出入り・転換・明確なビートの制御時だけ。

- **✕** 「1秒で3つの動作を完了する」(頻度指定は不可。レンジの重複・飛びも不可)
- **○** 連続・非重複のレンジで配分:`0〜3秒… 3〜7秒… 7〜12秒…`
- 正確な時点:「5秒の時点でカメラが左へ高速パン」/ 相対:「押してから3秒後、照明が徐々に消える」

## FIG 07 — 自動ロックされる3つ

プロンプトでは変えられない。

| モード | アスペクト比 | 尺 |
|---|---|---|
| 動画編集 | ロック | ロック(最大0.3秒ずれうる) |
| 初期/終端フレーム生成 | ロック(1枚目を採用) | 自由 |
| 動画の延長 | ロック | 自由(音量が僅かに変わることあり) |

## FIG 08 — 編集はマスターと範囲を切る

元動画を「唯一の編集マスター」と宣言し、**編集対象・編集範囲・ターゲット素材・保持する内容**を書く。
**差し替えは常に個数で固定する**(言わないと複製されて2つ映る)。
「元の対象の登場・動き・遮蔽・退出のすべてを、タイミング・軌道・速度変化ごと継承する」と書く。

## FIG 09 — 延長は境界フレームを先に書く

**順番が命。**先に「つなぎ目の連続性」、そのあとで「新しい出来事」。
維持:姿勢と向き / 小道具の位置 / 背景と空間関係 / カメラ位置と構図 / 照明 / 動きの方向。
後方延長は逆に、元動画の1フレーム目を延長の明示的な終了状態として定義する。
「そのあと元動画につなぐ」だけでは早出しや二度動きが起きる。

## FIG 10 — キーフレームは1枚 = 1役、順番も明示

独立したキーフレーム画像は、1枚のグリッドに詰めるより整合しやすい。
「@Image 1 から @Image 4 をこの順でキーフレームとして使う」と書き出し、各画像の主要状態を**1枚ずつ別々に**述べる。
**初期と終端の比率が違うと終端が引き伸ばされる。**
絵コンテは読み順(左→右、上→下)とスタイル除外(線画・文字ラベルは使わない)を書く。

## FIG 11 — ブロックアウトは粗と精細で書き方が変わる

- **粗(TIME & SPACE)**:単純ジオメトリで軌道・配置・カメラ・カット・照明・音のリズムをプレビュー
  → 幾何オブジェクトを1つずつ最終的な被写体に対応づけ、継承する時間情報と空間情報を書く
- **精細(RE-RENDER)**:構造・動作・カメラを保持したまま素材・色・人物・場面・スタイルを差し替える
  → 軌道線・座標軸・コントローラ・カメラ視錐台は消しておく

## FIG 12 — 転換は形の対応を言葉で渡す

**前の動画 → 後の動画 → きっかけの動作 → カメラ移動 → 視覚変化 → 到達状態 → 音の移行**、この順。
形の対応を明示する(例:傘の円縁 → 天窓の金属リング / 赤い布地 → 差し込む白い昼光)。

## FIG 13 — 感情語は見えるものに翻訳する

「緊張した」では解釈幅が大きすぎる。変化が1回なら**明確な手がかりを2〜4個**で十分。
例(緊張):視線がゆっくり緞帳へ / 眉が寄ったまま緩まない / 口元がわずかに引き結ばれる / 呼吸が浅く、やがて長く吐き出す

## FIG 14 — カメラ用語はそのまま書ける

EXTREME WIDE / WIDE / MEDIUM / CLOSE-UP / EXTREME CLOSE-UP はそのままでよい。
珍しい用語・解釈が割れる用語だけ、**対象の被写体 + 視覚的変化 + 前景/背景の関係 + 方向や速度**を添える。
絞りや焦点距離の数値も書けるが、意図した見え方を書くほうが明確。

## やってはいけない10のこと

1. 画像内の文字ラベルに任せる
2. 除外指定を書かない
3. 全素材を同時に出させる
4. 参照動画の動作を文章で描き直す(参照と競合。継承する属性だけ書く)
5. 1ステージに変化を何個も入れる
6. 「1秒で3動作」など頻度で指定する
7. 差し替え対象の個数を言わない
8. 「そのあと元動画につなぐ」で済ませる
9. 初期と終端で画像の比率が違う
10. 「この素材を動画にして」だけ書く

## 投げる前のチェックリスト(14項目)

- [ ] 主体と、主要な動作・出来事がはっきり書かれている
- [ ] 全素材に「使うもの」と「使わないもの」がある
- [ ] 人物・商品・小道具に名前が付き、参照へ紐づいている
- [ ] 参照は場面ごとに選ばれている
- [ ] 各ステージは変化1つ + 明確な終了状態を持つ
- [ ] 人数・服装・所有・空間関係が一貫している
- [ ] 編集はマスター・範囲・個数・保持内容を定義した
- [ ] 感情と撮影用語に、見える手がかりを添えた
- [ ] キーフレームは1枚1役、初期と終端は同じ比率
- [ ] 絵コンテ/ブロックアウトの継承内容を書いた
- [ ] 自動ロックされる比率と尺のルールに従っている
- [ ] 延長は境界の画・動きの傾向・音の連続性を確認した
- [ ] ワンクリック動画は役割・順序・動き・編集・音を定義した
- [ ] 転換は2本の役割・きっかけ・過程・到達状態を定義した

## そもそも保証されないこと

- タイムスタンプはフレーム精度の編集点ではない
- 編集プロンプトは重要な出来事が揃う確率を上げるが、フレーム単位の重なりは保証しない
- 字幕・数式・看板・製品仕様・フレーム単位のタイミングを正確にしたいなら、参照素材 + 生成 + ポストプロダクションを組み合わせる
- シームレス転換は連続性を目指すもので、ピクセル単位の保存は保証しない
- ワンクリック動画で画像順やキャラクター対応が重要なら明示する
